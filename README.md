# Plans Past Five

A turnkey content-and-tools website for women who want hobbies, weekend plans and friendships outside work. It combines a hobby directory, a long-form journal (articles), interactive planning tools and a product shelf that is ready for affiliate links but ships unmonetized.

It is a built starter site, not a running business. This repository makes no claims about traffic, revenue or search rankings. Read `docs/buyer/START-HERE.md` first. All counts (articles, hobbies, products, kits, pins, images, tests) are in `docs/buyer/INVENTORY.md`, generated by `node scripts/inventory.mjs`; this README does not repeat them.

## What is on the site

- **Find Your Thing**: a short hobby quiz with shareable results.
- **Make Some Plans**: a weekend and weeknight itinerary planner (time, vibe, company, budget).
- **What Should I Do Tonight?**: a quick idea picker, plus a starter-budget tool.
- **Hobbies**, **The Journal**, six themed sections, **Shop Your Hobby**, search and a saved-items list ("My Plans") that lives in the visitor's own browser.
- Trust pages: About, Contact, Editorial Standards, Methodology, Corrections, Affiliate Disclosure, Privacy, Terms, and a dated "What changed" page (`/changelog`) with the launch note (launched November 2026).

## Stack

TanStack Start (React 19, TypeScript, file-based routing), Vite, Tailwind CSS v4, Bun as the package manager. Tests run on Vitest and Testing Library. No database, accounts, payments or server secrets. The site is server-rendered (SSR), so the host must run a server function; it is not a static-file site.

## Quick start

```sh
bun install            # install dependencies
bun run dev            # local dev server (binds 127.0.0.1; open the address it prints)
bunx vitest run        # tests
bunx tsc --noEmit      # typecheck
bunx eslint .          # lint
bun run build          # production build (runs the content build first)
```

## Content workflow

Articles and images are plain JSON files, so they can be edited without touching code.

1. Edit or add files in `content/articles/*.json` and `content/images/`. You can do this by hand or through Pages CMS using `.pages.yml` (setup: `docs/buyer/CMS-SETUP.md`).
2. Run `node scripts/build-content.mjs` (also `bun run content:build`). It validates the content, lists any problem in plain English, and writes the compiled files to `src/content/generated/`. The build and CI run it automatically.
3. Commit both the JSON and the generated files.

A published article must have sources, a `verifiedAt` date and no open checks or the build refuses it (a field check, not a fact check).

Products are managed in Pages CMS (section Products, one file per product in `content/products/`); the build checks every product and every article mention before publishing. Owner steps: `docs/buyer/PRODUCT-MANAGEMENT.md`. The CSV importer (`bun run import:products`) is an optional developer bulk-load tool that only adds new product files.

## Deploy

Netlify is the configured host: `netlify.toml` holds the build (it sets the Netlify Nitro preset, publishes `dist` and uses a server-rendering function). One test deploy ran on the seller's own Netlify account; it is not transferred. Other hosts (Cloudflare, for example) are alternatives that need their own setup and verification, and the free Vercel Hobby plan is not recommended for a monetised site (its commercial-use terms were not found). To protect the free plan's deploy allowance, a PRODUCTION build runs only when the latest commit message contains the marker `[deploy]`; the CMS **Publish site** button (GitHub workflow `.github/workflows/publish-content.yml`) adds it for you, so a non-coder edits, previews and publishes in a browser (`docs/buyer/PUBLISH-AND-ROLLBACK.md`; not yet tested with a real login). Previews of the `content-edits` branch and pull requests always build and cost 0 credits. Developers can still deploy on purpose:

```sh
git commit --allow-empty -m "Release: what changed [deploy]"
git push
```

Budget: Netlify's free plan gives 300 credits a month, 15 per production deploy and 20 per GB of bandwidth, and the site pauses at the cap; plan for at most 8 deploys a month (`docs/buyer/NETLIFY-CREDITS-AND-RELEASES.md`, re-read live before relying on the numbers). Details: `docs/buyer/HOSTING-AND-DEPLOYMENT.md`. CI (`.github/workflows`) runs the content build, tests, typecheck and build on every pull request.

## What is not included

- No live domain, hosting account, active analytics (one empty setting, `analytics.ga4MeasurementId`, turns GA4 on), email list or affiliate accounts. You set these up under your own logins (`docs/buyer/ACCOUNT-DEPENDENCIES.md`).
- Affiliate links are not activated; the disclosure says links currently earn nothing.
- No traffic, revenue or ranking history.
- A working contact channel is yours to add (`docs/buyer/DOMAIN-AND-EMAIL.md`).
- Images are AI-generated; commercial-use and transfer terms are unverified, and no exclusivity or registrable copyright is promised. The per-image record is `docs/content/IMAGE-LICENCE-LEDGER.md`; read `docs/buyer/IMAGE-AND-ASSET-RIGHTS.md` before publishing.
- Licence: the code carries no open-source licence (`"license": "UNLICENSED"`, `"private": true`); see `docs/buyer/LICENCE-STATUS.md` and `THIRD-PARTY-NOTICES.md`.
- Amazon Associates: nobody has applied; the path and dated rules are in `docs/buyer/AMAZON-ASSOCIATES-PATH.md`.
- Things we do not claim (traffic, revenue, approved affiliate, exclusive images, trademark clearance, legal review, no-code editing of hobbies/products/config) are listed in `docs/buyer/START-HERE.md`.
