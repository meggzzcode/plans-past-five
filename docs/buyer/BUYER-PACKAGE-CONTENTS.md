# Buyer package contents (sanitised)

What ships to a buyer and what must not. **For the owner's approval before anything is sent.** The executable form of this list is `scripts/make-buyer-package.mjs`; if the two disagree, fix the script or this page so they match.

```
node scripts/make-buyer-package.mjs --list    # dry run: what ships, what is excluded, warnings; writes nothing
node scripts/make-buyer-package.mjs           # writes /tmp/plans-past-five-buyer-package-<date>.zip
```

The script is read-only on the repo, writes the zip only into the system temp directory (it refuses a path inside the repo), makes no network call and needs no install. It exits without writing if it finds a secret-looking string in a file that would ship. Run it from a clean, committed checkout so no uncommitted scratch files are packed. It does not decide access: hand the zip over only through the agreed channel (or transfer the repository instead; `docs/buyer/TRANSFER-CHECKLIST.md`).

## Must be excluded (and is)

| Excluded | Why |
| --- | --- |
| **Credentials of any kind**: `.env*`, `*.local`, `.dev.vars`, `*.pem`, `*.key`, tokens, passwords, API keys | The repo holds none (checked 2026-11-19); the script blocks the file names and scans shipped text for key-shaped strings |
| **Tax information** (tax IDs, forms, accounting records, payout details) | None is in the repo; never add any |
| **Master affiliate account material**: the seller's Amazon Associates or other affiliate accounts, tracking IDs, reports, login or payout details | Not transferable; the site ships with none (`src/config/affiliate.ts` is blank) |
| **Assets and notes of the seller's other business** (branding, analytics or tracking IDs, mailbox and domain set-up notes, `docs/launch/`, `docs/TURNKEY-PLAN.md`) | Must stay separate. The script refuses to write the zip if a shipped file names that business (the name is held in the script, not repeated here) |
| **Personal data**: the seller's personal email addresses, phone, home address, account numbers, order numbers and receipts | Not for a buyer. The script lists every non-company email address it finds so you can review them |
| **Internal agent and review notes**: all of `docs/marketplace/` except the three files above (reviews, `reviews2`, `reviews3`, `final-inspection/reviews`, working reports, pricing, listing drafts, Flippa research, QA and security working files), `docs/cowork/` prompts and logs, `docs/HANDLING-LOG.md`, `docs/RESUME.md`, `docs/process/LESSONS-LEARNED-CUSTOMER-REVIEW.md` | Working notes and negotiation positions, not deliverables. The pricing sensitivity table and the support proposal are the owner's private papers |
| **Build output and caches**: `dist/`, `.output/`, `.netlify/`, `.wrangler/`, `.tanstack/`, `node_modules/` | Regenerated by the buyer; build output carries seller project labels |
| **Version control**: `.git/` | Whether history is handed over is a separate owner decision (`docs/buyer/REPO-VISIBILITY.md`); a repository transfer includes it |
| **`.lovable/`** | The seller's Lovable project marker; the Lovable project, account and credits are not part of a sale |
| **Canva archive folders** (`docs/content/incoming-images/`, `sliced-tiles/`) | Archive sheets and tiles, not on the site; their terms are unverified |
| **Accounts and assets that are not files**: domain, mailbox, hosting, analytics, Pinterest, Amazon | Handed over (or created) by the buyer; the domain and mailbox are an owner decision |

## Known gaps in the package

- Some shipped documents still mention files that are not shipped (the script prints them under "References ... NOT in the package"): chiefly pointers to the seller's marketplace reports and Cowork task files. They are harmless but confusing; fix or accept.
- Two tests are sensitive to the package: `src/test/buyer-docs.test.ts` (START-HERE links only to files that exist) and `src/test/catalog-import.test.ts` (the verification queue CSV). Both pass in a package built by the script; re-run `bunx vitest run` in an extracted copy before sending.
- The zip is a snapshot of the working tree, not of git history. Commit first so the working tree is what you mean to ship.

## Before you send anything (owner checklist)

1. Run `--list`; read every email address and warning it prints.
2. Build the zip; extract it into an empty folder; `bun install --frozen-lockfile`, `bunx vitest run`, `bunx tsc --noEmit`, `bun run build` in that folder (not in the repo).
3. Confirm nothing in it names another business, a personal account or a price you have not decided to share.
4. Send by the agreed channel; record what was sent and when.
