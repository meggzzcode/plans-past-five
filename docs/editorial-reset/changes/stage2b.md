## 2. Why legitimate owner edits failed tests (investigation)
Pages CMS source (`lib/serialization.ts`, read 2026-11-19) writes JSON with `JSON.stringify(obj, null, 2)`: 2-space indent and **no trailing newline**. The project's canonical layout ends with a newline and uses schema key order, so the old "byte-stable" test (`onDisk` must equal `articleToJson`) failed after **every** Pages CMS save of an article, and after any stale generated bundle. Root causes found and fixed:
1. Byte-for-byte file equality (typo edit, different indent, CMS layout). Now: meaning equality (parsed data vs compiled bundle), a canonical-layout idempotence check, a CMS-style-save test, and the build tidies the layout. A valid save never fails a test.
2. Generated files stale until a separate command ran. Now the suite builds content first (global setup).
3. Scratch copy in `build-content.test.ts` lacked `public/uploads`. Now copied.
4. Values asserted instead of behaviour: GA4 empty, contact email not a placeholder, manifest name, `Plans Past Five` in shop copy text, verification tags empty, `validGa4Id(undefined)`, hobby counts (43), group-size bounds, `https://planspastfive.com` in og:image. All derived from settings/data now.
5. A latent bug: a noindex hobby page with a picture still emitted og:image (the pins test caught it only when a hobby had no article). Fixed in the route.
6. The new-article file name: `.pages.yml` uses `filename: "{primary}.json"` with primary `title`; whether Pages CMS names the file after the title or the slug is UNKNOWN until the real test. The tests now find article files by slug, so either works.
